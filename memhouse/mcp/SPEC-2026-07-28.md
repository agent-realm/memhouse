# MCP 2026-07-28 — ground truth (P0)

Read 2026-08-16 from the spec itself, not from memory:

- https://modelcontextprotocol.io/specification/2026-07-28/changelog
- https://modelcontextprotocol.io/specification/2026-07-28/basic/lifecycle (versioning + compatibility)

Spec terminology: **modern** = `2026-07-28` and later (per-request metadata).
**legacy** = `2025-11-25` and earlier (`initialize` handshake). **dual-era** =
supports both.

## The stateless flow

No handshake, no session. One request, one result:

```
client → server:  tools/call   (_meta carries version + caps + identity)
server → client:  result       (_meta carries serverInfo; result has resultType)
```

Request `_meta` keys:

| Key | Note |
|---|---|
| `io.modelcontextprotocol/protocolVersion` | on EVERY request |
| `io.modelcontextprotocol/clientCapabilities` | on every request |
| `io.modelcontextprotocol/clientInfo` | SHOULD |
| `io.modelcontextprotocol/logLevel` | optional; server **MUST NOT** emit `notifications/message` for a request that omitted it |
| `traceparent` / `tracestate` / `baggage` | OpenTelemetry propagation convention |

Result: `io.modelcontextprotocol/serverInfo` in `_meta`, and a **required**
`resultType` — `"complete"` or `"input_required"`. Clients MUST treat a missing
`resultType` (earlier-protocol server) as `"complete"`.

Version mismatch is per request, not per connection:

```json
{"jsonrpc":"2.0","id":1,"error":{"code":-32022,
 "message":"Unsupported protocol version",
 "data":{"supported":["2026-07-28","2025-11-25"],"requested":"1900-01-01"}}}
```

`server/discover` — servers **MUST** implement; clients **MAY** call it first for
up-front version selection, or use it as the stdio backward-compatibility probe.

## Modern vs legacy

| Aspect | legacy (≤2025-11-25) | modern (2026-07-28) |
|---|---|---|
| Open | `initialize` + `notifications/initialized` | none — first request is real work |
| Version / caps | negotiated once, held in session | in `_meta` on every request |
| HTTP session | `Mcp-Session-Id` header, sticky routing | removed |
| List endpoints | may vary per connection | fixed; same answer to every caller |
| Cross-call state | server-side session | server-minted handles passed as ordinary tool arguments |
| Server→client asks | server-initiated `roots/list`, `sampling/createMessage`, `elicitation/create` mid-request | MRTR: result `resultType:"input_required"` + `inputRequests`; client RETRIES the original request with `inputResponses`; server correlates via its own `requestState` |
| Server→client notifications | HTTP GET + SSE; `resources/subscribe`/`unsubscribe` | `subscriptions/listen` — one long-lived POST stream, opt-in types (`toolsListChanged`, `promptsListChanged`, `resourcesListChanged`, `resourceSubscriptions`), tagged `io.modelcontextprotocol/subscriptionId`. Request-scoped `notifications/progress` and `notifications/message` still ride their own request's response stream |
| Stream resume | `Last-Event-ID`, SSE event IDs, redelivery | removed — a broken stream loses the request; re-issue with a NEW request id |
| HTTP request | POST body only | POST + required `Mcp-Method`, `Mcp-Name`, `MCP-Protocol-Version` headers; `x-mcp-header` for custom headers from tool params |
| Caching | `listChanged` notifications only | `CacheableResult` — `ttlMs` + `cacheScope` (`"public"`/`"private"`) REQUIRED on `tools/list`, `prompts/list`, `resources/list`, `resources/read`, `resources/templates/list`. `tools/list` SHOULD be deterministic-ordered |
| Removed methods | — | `ping`, `logging/setLevel`, `notifications/roots/list_changed`, `resources/subscribe`/`unsubscribe`, `notifications/elicitation/complete` |
| Deprecated | — | Roots, Sampling, Logging (12-month window); HTTP+SSE transport; OAuth DCR (RFC7591) → Client ID Metadata Documents |
| Tasks | experimental, in core | extension `io.modelcontextprotocol/tasks`; polling `tasks/get` + `tasks/update`; `tasks/list` removed; handles may be returned unsolicited |
| Error codes | `-32002` resource-not-found | `-32602` resource-not-found. Range policy: `-32000`–`-32019` implementation-defined, `-32020`–`-32099` reserved for the spec. `HeaderMismatch` `-32020`, `MissingRequiredClientCapability` `-32021`, `UnsupportedProtocolVersion` `-32022` |
| Schemas | integer-typed bounds; constrained `structuredContent` | any JSON Schema 2020-12 keyword in `inputSchema`/`outputSchema`; any JSON value in `structuredContent`; `$ref` resolution requirements |

Extensions are negotiated through an `extensions` map on `ClientCapabilities` /
`ServerCapabilities` — identifier → settings object, prefixed like a `_meta` key.

## What this means for memhouse

Mandatory surface, and it is small:

- implement `server/discover`
- read `_meta` per request; return `io.modelcontextprotocol/serverInfo`
- stamp `resultType: "complete"` on every result
- `ttlMs` + `cacheScope: "private"` on `tools/list` (and on `resources/read` if P7 happens)
- deterministic tool order

Not needed, at all: MRTR (`input_required`) — our tools are read-only and ask the
client for nothing. `subscriptions/listen` — nothing changes under the client
mid-call. Roots / Sampling / Logging — we use none, so the deprecations cost zero.

**Plan correction:** on Streamable HTTP (P6) the required headers are THREE, not
two — `MCP-Protocol-Version` alongside `Mcp-Method` and `Mcp-Name`. Also note
there is no GET endpoint to mount any more.

Backward compatibility, if we ever want dual-era: a stdio client probes with
`server/discover` and falls back to `initialize` on any non-modern error; an HTTP
client inspects the body of a `400 Bad Request`. Era is a property of the server,
cached for the server process (stdio) or origin (HTTP). A modern-only server
SHOULD name its supported versions in whatever error it returns to `initialize` —
legacy clients have no fall-forward path and that message is their only diagnostic.
