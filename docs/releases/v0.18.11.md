# memhouse 0.18.11 — 2026-10-08

This release does three things:

- **Sessions with subagents stop re-shipping.** A Claude Code session that used subagents
  now ships only its new rows. Before, it re-sent itself whole on every pass, and that was
  most of the house's write load.
- **A security fix.** `invite` no longer sends a stored credential to whatever `--url` is
  typed on the command line.
- **The 0.18.10 pre-tag list is finished**, and the gentar test kit is bumped.

**No drill was run for this release; waived (2026-10-08) under the pilot's 0.18.10 ruling. The drill runs before 0.19.0.**

## Read this before upgrading

**The first pass after the upgrade is a one-time bulk write.** It re-sends, whole and once,
every stored session that has subagents; after that, those sessions ship only their new
rows. Two things widen that first pass:

- **Sessions whose subagents wrote recently.** A session whose subagent files are newer
  than the house's record of it is read again even if it did not grow, because
  `lastUpdatedAt` now counts subagent writes.
- **Installs that share session files.** Two installs that ship the same session files
  (two instances on one machine, or a synced directory) must be upgraded together. A
  0.18.10 and a 0.18.11 number the same session differently, and each would fork it back
  on every pass.

**Where that write lands, and when to do it (2026-10-08):**

- The pilot's machines (macminim, macbokum) ship to **zeo.memhouse.io**: VM 146 on arf,
  ClickHouse 26.7.4.58.
- It is **not** LXC 112 "memhouse-production"; that is an archive, not a live house.
- zeo's data disk still sits on arf's degraded array. It was backed up to SSD on
  2026-10-08 (data and access storage), but the disk itself has not moved.
- **Upgrade those machines only once zeo's data disk is off the degraded array, or once
  the array is repaired. Time it against the SSD moves.**
- Any house on healthy storage can upgrade normally.

```bash
memhouse update        # then: memhouse status — every line a check mark
```

## Security

### `invite` never sends a stored credential to `--url` (G4)

`--url` is the invitee's address, typed on a command line. A typo, a tunnel, or somebody
else's server received credentials it should never have seen:

- the member's own credential, through the reachability probe and the read of its grants;
- an admin credential the install keeps, through provisioning.

The cause: `resolveConfig()` lets a flag outrank the env file, so the "configured house" URL
the code used *was* `--url`.

Now:

- **A stored credential goes only to the house it was saved for.** That covers the
  member's own, a `--keep-admin` admin, and a password read from the env file.
- **`--url` gets an unauthenticated `/ping`**, only to confirm the invitee can reach it.
- **An admin given for this command** (`--admin-user`, or an exported
  `MEMHOUSE_ADMIN_USER`, with its password from a file, stdin, the environment or a prompt)
  still provisions at `--url`. That is what the person typing the command asked for.
- **`misc/invite-matrix.sh` points `--url` at a spy server** and asserts that it receives
  nothing but a ping. On 0.18.10 the spy received two authenticated requests.

**Action:**

- If you ran `memhouse invite … --url <something unusual>` on 0.18.10 or earlier against a
  host you do not control, rotate the member's password with `memhouse passwd`.
- If an admin credential is kept in the env file and the same applies, rotate that too.

## The re-ship fix (#21)

Folded subagent rows were numbered by position, after the parent's turns. One new parent
turn moved every one of them, so the session forked to a new epoch and was re-sent whole.
Measured on a real house:

- 1.07 M message rows written in 24 h, against 10.2 M in total;
- one 6,120-line session stored 60 times in a day;
- polat's house at about 19 M message rows for roughly 295 k real ones.

What changed:

- **Subagent rows get a numbering block of their own:**
  `seq = 1,000,000,000 + slot × 100,000 + turn`, and the same for tool calls' `idx`.
  `slot` is the subagent's rank by start time, so neither the parent growing, a subagent
  growing, nor a new subagent appearing moves a stored row.
- **A session without subagents is numbered exactly as before.**
- **`seq` is sparse.** Count rows with `count()`, never `max(seq) + 1`.
- **`ORDER BY seq` groups subagents.** Readers see the parent first, then each subagent's
  turns together, in the order the subagents started. They used to be in agent-id order,
  which is random.
- **A parse too big for the blocks falls back to positional numbering:**
  - a parent past 1e9 turns;
  - a subagent past 100,000 turns;
  - more than 32,949 subagents.

  Positional numbering is correct, and merely re-ships whole as before.
- **Subagent writes count as session activity.** A subagent that keeps running after its
  parent goes quiet is shipped on the next pass.
- **A subagent caught before its first line is written holds its session for one pass.**
  It is then ranked by its real start time; it no longer ranks last and moves later. A
  file that never gets a timestamped line stops holding the session after 10 minutes.
- **Existing copies are not cleaned up.** Superseded epochs already in a house stay;
  memhouse never deletes to make room. Reclaiming that space is a separate operator
  decision, and no such cleanup may run on a house on degraded storage.

## Also fixed

- **The dashboard no longer goes empty on a quiet house (G11).** The stats tables carry a
  one-day TTL and were refreshed only by passes that shipped something.
  - The shipper now also refreshes them when the newest generation is over an hour old.
  - The dashboard re-resolves its tables every five minutes, falling back to the live
    rollup when a stats table is empty.
- **The skills find their reference again (G26).** All five pointed at
  `../reference/HOUSE.md`, a path that does not exist in the installed plugin; the file is
  at `../../reference/HOUSE.md`.
- **`/mem:recall`'s queries run (A2).**
  - "Recent sessions" used a column the room does not have.
  - The search now returns the `hit_seq` that the transcript read needs.
  - The read takes its window by position, so the subagent blocks cannot break it.
- **`HOUSE.md`'s subagent queries keep to the current parse (A3).** They used to double a
  re-parsed session's subagent turns.
- **An option that takes no value no longer swallows the next word (A6).**
  `update --no-install yes` ran the install it was told to skip, and `share --revoke bob`
  revoked nobody.
- **`update --channel <name>` pins only a tag the registry has (A5).** Before, it never
  wrote the pin at all.
- **`update --no-install` restarts a tarball or nightly install.** That is the command
  every nightly build prints for itself. On exactly those builds it stopped at "no
  automatic update for this install" and exited 1, leaving the old shipper running old
  code. It now restarts the daemons, runs any migration, and checks the schema; it needs
  no channel.
- **`update --no-install` (A6)** no longer prints "files updated", and it is no longer
  refused on a project-dependency install.
- **The epoch log line counts rows (A4).**
- **Docs (A8): the host id is derived from the machine's own id**, as it has been since
  0.18.6, so a reinstall keeps it. Stale prose about timestamps and `extra.turn` is fixed
  too.

## License notices

**The dashboard now ships the license notices of what it bundles.** The built dashboard
(`public/`) includes React, chart.js, lucide-react, react-markdown, tailwindcss and every
other package it bundles. Their licenses (MIT, ISC) require the notice to travel with each
copy, and minification strips it from the code.
- `public/THIRD_PARTY_NOTICES.txt` is now generated at build time from the bundle's module
  graph, and ships in the npm package.
- CI fails a package that lacks it.

Earlier published packages carried those copies without the notices.
