# memhouse 0.18.10 — 2026-10-08

A security release:

- an admin password no longer has to go on the command line;
- no command prints a member password;
- a scoped share no longer reaches past its scope.

Everyone on 0.18.x should upgrade.

**No drill was run for this release; waived by the pilot (2026-10-08). The drill runs before 0.19.0.**

```bash
memhouse update        # or: npm install -g memhouse@latest, then memhouse update --no-install
memhouse status        # every line a check mark
```

Nothing in the house changes: no migration, no new room, no re-ship. Machines on 0.18.9
and 0.18.10 can ship into the same house side by side.

## Security

### An admin password never has to go on the command line (#14)

The admin-assisted commands (`install --member`, `invite`, `passwd`, `convert`,
`members`) now take the admin password from, in order:

1. `--admin-password-file <file>`, a file holding the password (one trailing newline is
   dropped), or `--admin-password-file -` to read it from stdin;
2. `--admin-password <value>` (still accepted, with a warning; see below);
3. `MEMHOUSE_ADMIN_PASSWORD` in the environment, which is how `with-secret` lends a secret
   to one command;
4. a credential this install already keeps, but only for the same admin user;
5. a prompt, when there is a terminal to prompt on.

```bash
with-secret MEMHOUSE_ADMIN_PASSWORD=keychain:pilot/house-admin -- \
  memhouse invite alice --url https://house.example.com --admin-user default
printf '%s' "$ADMIN_PASSWORD" | memhouse invite alice --url … --admin-user default --admin-password-file -
```

Before this release, `--admin-user` as a flag switched every other source off. The only
scriptable admin path therefore put the password on argv, where `ps` shows it for as long
as the command runs and shell history keeps it. Found by O's sandbox rehearsal (finding 6).
With no source and no terminal, the command stops and prints the three ways above instead
of hanging or guessing.

### An admin install no longer saves the admin credential (#14)

`install --admin-user …` builds the member and then ships as the member. It used to write
the admin credential into `~/.memhouse/env` as well. The help said it was saved; every
agent-facing text said it never was. Now it is saved only with `--keep-admin`, or when
the env file already keeps that same admin. Credentials already saved keep working.

### A daemon never carries the admin credential (#14)

- Service units (systemd, launchd) drop `MEMHOUSE_ADMIN_*` before they inline the env.
- The shipper and the dashboard are started without it, even when the shell exported it.
- `deploy --local` passes the ClickHouse password to `docker run` through the environment,
  no longer as `-e CLICKHOUSE_PASSWORD=<value>` on its argv.

A unit test now fails on any spawn or exec in the shipped code that puts a password on
argv.

### No command prints a member password (G23)

`install --admin-user` used to show the generated member password once, on the terminal.
It was already written to the env file, so the terminal copy served no one. It landed in
scrollback and, through `/mem:access` and `/mem:admin`, in an agent's transcript, which
memhouse ships into the house, where the archive is insert-only. (#20)

- **Install and invite never print a generated member password.** It goes to the env file
  (install) or the invite file (invite), and nowhere else.
- **A failed install cleans up after itself.** If the grant fails after the member was
  created, the run drops that member, so no account is left with a password nobody holds.
- **`install --print-sql` and `invite --print-sql` print a placeholder,
  `IDENTIFIED BY <member-password>`.** As printed, that line does not parse. The
  administrator puts a quoted password they generate in its place, and the same password
  goes into the env-file lines the command prints for the member. From `invite`, those
  lines carry `MEMHOUSE_INVITE=1`, so the member's `install --env` offers to rotate it.
  A `--member-password` given with `--print-sql` is not echoed.
- **Tests guard it.**
  - A unit test fails on any print call that evaluates a password: as an argument,
    concatenated, or interpolated.
  - `misc/invite-matrix.sh` runs every install, invite and passwd path against a real
    ClickHouse and checks each output against the real passwords.

### A scoped share shares only what its scope filters (#13)

`memhouse share <user> --only <scope>` granted `SELECT` on the member's whole pattern,
`mem.<member>_*`, while its row policies covered only `sessions`, `messages` and
`tool_calls`. A grantee scoped to one project could therefore read these in full:

- `<member>_session_stats`: the opening prompt, folder, project and token totals of
  every session in every project;
- the model and tool stats;
- `<member>_meta`, including the member's other `share:` records;
- `<member>_events`;
- any table the pattern matched later.

Now:

- **A scoped share is granted table by table,** on exactly the three filtered rooms.
  Narrowing an existing full share to a scope takes the wildcard back first, so a failure
  part-way leaves the grantee with less access, never more.
- **`--revoke` withdraws the grants before it drops the row policies.** The old order
  failed open: a `REVOKE` refused after the policies were gone left an unfiltered share.
  A failed cleanup now keeps the policies unless every grant is confirmed withdrawn.
- **`--only ""` and whitespace-only scopes are refused.** An unset `--only "$SCOPE"`
  used to fall through to a full share.
- **The permissive-server check before a scoped share runs.** Its probe table sat
  outside the member's grant, so it was refused on every server and always reported
  "could not verify".

A full share (no `--only`) is unchanged: it reaches everything in `mem.<member>_*`, by
design, and says so.

**Action for existing scoped shares:** they keep their old wildcard until re-run. On the
sharing member's machine, run `memhouse share <user> --only <scope>` again for each one;
`memhouse share --list` shows them.

## Deprecations

| what | since | removed in | use instead |
|---|---|---|---|
| `--admin-password <value>` on the command line | 0.18.10 (2026-10-08) | **0.19.0** | `MEMHOUSE_ADMIN_PASSWORD` (via `with-secret`), `--admin-password-file <file>`, or `--admin-password-file -` |

It still works in 0.18.x and prints one warning on stderr. Move scripts now.

## Upgrading

- **One machine:** `memhouse update`. The daemons restart on the new code.
- **Upgraded by hand** (`npm install -g memhouse@latest`): run
  `memhouse update --no-install` afterwards to restart the daemons.
- **Several machines on one house:** no ordering is needed. This release changes no row
  shape, no room and no shipper behaviour.
- **Share owners:** re-run each scoped share once (above).
- **Scripts and CI that pass `--admin-password`:** move to `MEMHOUSE_ADMIN_PASSWORD` or
  `--admin-password-file` before 0.19.0.
- **Scripts that read a member password from `install --admin-user` output:** read
  `MEMHOUSE_PASSWORD` from the env file instead. The output no longer contains it.
- **Scripts that run `--print-sql` output as is:** put a quoted password where
  `<member-password>` stands. As printed, the line is refused by the server.
- **If an admin credential is in `~/.memhouse/env`** and you did not mean to keep it,
  remove the `MEMHOUSE_ADMIN_USER` / `MEMHOUSE_ADMIN_PASSWORD` lines. memhouse never
  needs it to ship.

## Also in this release

- **The documentation standard** (#17). See [Documentation](#documentation) below. This
  does change the package: it now also ships `docs/`, `examples/`, `AGENTS.md`,
  `SECURITY.md` and `CHANGELOG.md`.

These do not change the installed package:

- **CI's tarball audit can fail now.** Its forbidden-file check was `! grep`, which
  `set -e` never acts on, so it passed whatever the tarball held.
- **gentar arena adoption** (#10). memhouse is now a gentar subject. Its suites are
  `memhouse-house` and `memhouse-install`, kit v0.9.2, and they install from `npm pack`
  exactly as a publish ships. The phase-1 check runs on GitHub-hosted runners on every
  push and PR. Full arena runs need a self-hosted bench; the one used before the
  repository went public was deregistered then.
- **memhouse.io describes 0.18** (#12): one layout, five skills, the honest editor count
  (16 adapters reading 18 apps).
- `memhouse.io/.wrangler` (wrangler's local cache) is no longer tracked.
- `misc/one-layout-matrix.sh` now asserts the scoped-share boundary, and
  `misc/invite-matrix.sh` the admin-password sources: environment, stdin, `--keep-admin`,
  and none. The file source is covered by unit tests. CI runs both matrices against
  ClickHouse 25.11 and 26.7.

## Documentation

This release meets the documentation standard (#17):

- a short README: what memhouse is, why, and how to install it;
- `docs/`, with three tutorials and twelve guides;
- `examples/`, four runnable setups from one machine to a self-hosted team house, each
  with its own README;
- an install and deploy section for agents in `AGENTS.md`.

The npm package now ships `docs/`, `examples/`, `AGENTS.md`, `SECURITY.md` and
`CHANGELOG.md`, so an installed copy carries its own manual. `change.log` (#19) lists
every tag and what it changed.
